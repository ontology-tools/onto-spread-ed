# CLAUDE.md - Project Context for AI Assistants

## Project Overview

**OntoSpreadEd** (Ontology Spreadsheet Editor) is a Python/TypeScript monorepo for collaborative editing of OWL ontologies through spreadsheet interfaces. It enables domain experts to work with complex ontologies using familiar Excel-like views without requiring deep OWL syntax knowledge.

## Repository Structure

```
onto-spread-ed/
├── packages/                    # Core packages
│   ├── ose-lib/                # Python: Core library (project config, ontology building)
│   ├── ose-app/                # Python: Flask backend (JSON API, OAuth, serves the SPA)
│   ├── ose-cli/                # Python: Command-line interface

│   └── ose-js-app/             # TypeScript/Vue: the single-page web app
```

## Architecture

The web UI is a single Vue 3 SPA (`packages/ose-js-app`: `index.html` + `src/main.ts`, vue-router in history mode).
There are no server-rendered pages.

- Flask (`ose-app`) serves only `/api/*`, the OAuth routes (`/login`, `/logout`, `/github-callback`), `/user`, `/status` and static files.
- `routes/spa.py` is the catch-all (registered last) that serves the SPA. It reads `static/app/index.html`, injects
  `window.OSE_CONFIG = {prefix}` and the importmap at the `<!--ose-head-->` marker, and rewrites the relative asset URLs
  (`="./`) to `{URL_PREFIX}/static/app/`. `URL_PREFIX` is therefore a runtime setting. There is no `<base>` tag; the router
  base comes from `OSE_CONFIG.prefix` (`src/config.ts`).
- `/api/*` never redirects or renders HTML: auth failures are always JSON `401`/`403` (`{success: false, error}`).
- Page data comes from the JSON API (see `packages/ose-app/API.md`). `/api/me` provides the user, permissions and app info.
- Frontend internals (routes, `api()` helper, layout state, adding a page): `packages/ose-js-app/README.md`.

### Plugin loading

Plugin components are built with `vue` and `@ontospreaded/js-core` as externals. At runtime the importmap in `index.html`
maps these bare imports to `static/app/vue-shim.js` / `ose-js-core-shim.js`, which re-export `window.Vue` /
`window.OseJsCore`. `main.ts` sets those globals at bootstrap. Plugin modules are loaded via dynamic import from
`/api/plugins/<id>/static/<js_module>`. The shims are generated by `scripts/generate-shims.mjs` into `packages/ose-js-app/public`.

## Plugin System

Plugins use Python entry points for discovery:

```toml
# In plugin's pyproject.toml
[project.entry-points.'ose.plugins']
my_plugin = "my_package:MY_PLUGIN"
```

Plugins can provide:
- **ReleaseStep** subclasses for ontology release pipelines
- **Script** subclasses for custom automation
- **Vue components** for UI customization (via `js_module` and `static_folder`)

## Important Notes

1. **Build Order**: js-core -> shims (into `ose-js-app/public`) -> js-app (-> `ose_app/static/app`) -> plugins -> Python wheels. `npm run build` covers the first three, `make build-js` adds plugins, JS must be built before Python packages (static assets are included in wheels)
2. **Workspace Dependencies**: Use `workspace = true` in `[tool.uv.sources]` for local packages
3. **Plugin Static Assets**: Plugin JS/CSS goes in `src/<plugin_package>/static/`
4. **Dev Workflow**: `make dev` (or `npm run dev` plus `make dev-python`), then open http://localhost:5173. The vite dev server injects `OSE_CONFIG` and the importmap itself and proxies server paths to Flask on :5000 (override with `FLASK_PORT`, e.g. `FLASK_PORT=8080 npm run dev` for the VS Code debug config). `npm -w @ontospreaded/js-app run watch` keeps the old `vite build --watch` flow (open Flask on :5000).
5. **Database Migrations**: Run with `flask --app ose_app:create_app db upgrade`
